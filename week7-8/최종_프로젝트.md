## 3. 필수 사용 개념 (최소 1개 선택)

7개 중 **최소 2개**를 프로젝트에 실제로 넣는다.

**① Memory (RNN)**
메모리(기억)을 켜서 과거 관측을 기억하는 에이전트.

**② Camera / CNN (Visual Observation)**
Camera Sensor 또는 Render Texture로 **화면 픽셀을 그대로** 관측에 넣는다.
`vector_observation` 없이 화면만 보고 플레이하게 만들기. `conv_encoder` 선택 가능.

**③ GAIL (모방 학습)**
Demonstration Recorder로 **사람 플레이를 녹화(`.demo`)** 한 뒤, GAIL 보상으로 학습을 부트스트랩.
보상 설계가 어려운 문제(래그돌 걷기, 격투 콤보)에 특히 효과적. BC(Behavioral Cloning) 병행 가능.

**④ Custom Sensor**
`ISensor` / `SensorComponent`를 직접 구현하거나 Ray Perception Sensor를 목적에 맞게 커스텀.
예: 시야각(FOV) 안의 적만 감지하는 센서, 주차 공간까지의 거리·각도 센서, 그리드 점유 센서.

**⑤ Curriculum Learning + 환경 파라미터 랜덤화**
쉬운 난이도 → 어려운 난이도로 자동 승급. `environment_parameters`에 `curriculum` 또는
`sampler`(uniform/gaussian)를 정의해 **일반화 가능한** 에이전트를 만든다.
(주차 공간 크기, 파이프 간격, 바람 세기 등을 단계별로 조절)

**⑥ Self-Play / 멀티 에이전트 (MA-POCA)**
대전형이면 `self_play` 블록으로 과거 자신과 싸우게 하고(ELO로 성장 확인),
협동형이면 `MA-POCA` + Team ID로 팀 단위 보상을 학습.
오목·격투·숨바꼭질·눈싸움처럼 **상대가 있는 문제**에 필수급.

**⑦ Action Masking (+ 행동 공간 설계)**
Discrete 행동에서 `WriteDiscreteActionMask`로 **불가능한 행동을 매 스텝 마스킹**.
오목의 이미 둔 자리, 쿨타임 중인 스킬, 벽 방향 이동 등을 막아 탐색 공간을 크게 줄인다.

## 4. 깃허브 사용 규칙

개인 과제와 달리 **최종 프로젝트는 upstream에 PR을 날려서 마무리**한다.

### 4.1 흐름

```bash
# 0. (최초 1회) fork & upstream 등록
git clone https://github.com/<본인계정>/2026-PCUBE-RL-Study.git
cd 2026-PCUBE-RL-Study
git remote add upstream https://github.com/pandora-cube/2026-PCUBE-RL-Study.git
git lfs install

# 1. 최신 베이스 동기화
git fetch upstream
git checkout main
git merge upstream/main

# 2. 최종 프로젝트 브랜치 생성 (fork에서 작업)
git checkout -b final-<본인이름>-<프로젝트명>
# 예: final-jaehyun-autoparker

# 3. 작업 → 커밋 → 본인 fork에 push
git add .
git commit -m "final: 주차 보상 함수 설계 및 1차 학습"
git push origin final-jaehyun-autoparker

# 4. 마감일에 upstream main ← 본인 브랜치로 Pull Request
```

### 4.2 규칙

- **작업은 반드시 본인 fork의 브랜치**에서. upstream `main` 직접 push 금지.
- 브랜치명: `final-<본인이름>-<프로젝트명>` (소문자, 하이픈)
- 커밋 단위는 **작업 단위**로. "2주치 한 번에 커밋" 금지 (진행 과정이 곧 평가 자료)
- **PR은 1인 1개.** 제목 `[Final] <프로젝트명> - <이름>`, 본문에 데모 GIF와 학습 그래프 첨부
- PR 올린 뒤 다른 사람 PR **최소 1개에 리뷰 코멘트** 남기기

### 4.3 제출 디렉토리 구조

```
week7-8/
└── <프로젝트명>-<이름>/
    ├── README.md              # 필수 (아래 항목 포함)
    ├── UnityProject/          # Unity 프로젝트 (Assets/, ProjectSettings/, Packages/)
    ├── configs/
    │   └── <프로젝트명>.yaml  # 학습 config
    ├── models/
    │   └── <프로젝트명>.onnx  # 최종 학습 모델
    └── assets/
        └── demo.gif           # 데모 GIF (또는 README에 영상 링크)
```
